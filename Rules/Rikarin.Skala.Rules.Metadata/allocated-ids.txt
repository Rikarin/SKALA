# ADR-012: a rule id is allocated once and never re-purposed.
#
# One line per allocated id: `<id> <concept>`. The concept is a stable slug for what the rule
# means, and it is what makes this file more than a list of numbers — a baseline is a set of
# (rule, file, hash) tuples, so a redefined rule silently un-suppresses or wrongly suppresses
# findings in every repository that has one.
#
# RuleCatalogTests.RuleIds_AreAppendOnly asserts that every line here is still present in
# rules.json with the same concept. A line is never deleted.
#
# ⚠ A line may carry a `retired` marker after its concept, and retirement has two shapes that are
# not interchangeable:
#
#   * Retired AFTER shipping — the rules.json entry stays and carries `"retired": true`. The
#     descriptor survives disabled, so nothing new is reported but `dotnet_diagnostic.<id>.severity`
#     still resolves instead of dangling, and docs/rules/<id>.md stays as a tombstone an old finding
#     can be looked up in. SK1020 and SK1034 are this kind (#281).
#   * Retired BEFORE it was ever built — there is no rules.json entry to flag, so this file is the
#     only record. SK6001 is this kind, and it is why the marker exists at all.
#
# RuleCatalogTests.RetiredIds_AreRecordedInTheRegister_AndNeverShip asserts both shapes, and asserts
# the consequence rather than the flag: a retired id's descriptor is not enabled by default.
